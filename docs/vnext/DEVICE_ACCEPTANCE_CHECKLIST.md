# PaperScan vNext 物理Android端末での受入チェックリスト

更新日: 2026-11-12

この表は物理端末固有の最終確認に限る。実画像データセット評価、デスクトップPDFビューア確認、性能測定の再現性評価など、端末なしでも可能な未完了作業は[今回の継続記録](testing/2026-11-12_CONTINUATION.md)に分けて記載する。各項目は端末名、Android版、アプリのコミット、入力資料の条件、結果を記録する。

| 項目 | 操作手順 | 期待結果・合格条件 | 失敗時の調査対象 |
|---|---|---|---|
| カメラ権限・初期化 | 新規インストール後にカメラ画面を開き、拒否→再許可を試す | 拒否時は説明と戻る操作が使え、許可後にプレビューが開始する。クラッシュしない | 権限状態、CameraProvider bind、Camera2ログ、端末のカメラ占有 |
| 検知枠の位置 | 四隅を目視できるA4紙を平置き・斜め・画像端付近で撮影画面に映す。端末を縦横に回す | 枠が実際の紙の四隅と同じ位置に表示され、FIT_CENTERの余白へずれない。位置差をスクリーンショットで記録する | ImageProxy cropRect/rotationDegrees、ViewPort、CoordinateTransform、PreviewViewのサイズ |
| 検知枠の安定性 | 紙を数秒静止、移動、フレーム外へ出し、再度入れる | 静止後に枠が現れ、見失った枠は消え、再出現する。古い枠が残らない | 3フレーム安定化、250 ms間引き、Analyzer close、UI投稿順 |
| 手動連続撮影 | 10ページを手動シャッターで続けて撮り、連打と保存中の戻る操作も試す | 各押下は最大1ページを作り、撮影枚数・直近サムネイル・ページ順が一致する。撮影後もプレビューが続く | ImageCapture callback、busy/takingPicture、保存失敗、ライフサイクル |
| 撮影と編集の整合 | 台形紙を撮影し、自動枠と保存画像の四隅を比較して手動補正する | 補正後の紙面が自然で、元画像を再表示できる | EXIF、保存画像と解析フレームの寸法・回転、射影変換 |
| ライフサイクル | カメラ画面中にホームへ移動、復帰、画面回転、別アプリでカメラ使用後に戻る | 再バインド後にプレビューとシャッターが復旧し、古い枠と二重保存がない | ProcessCameraProvider、UseCaseGroup、遅延bind、Executor |
| 実機処理量 | 同条件の1/10/20/30ページを取り込み、補正・OCR・PDF出力を各3回実施する | クラッシュ、ANR、データ消失がない。時間、PDF容量、ピークメモリ、空き容量を記録し、受入しきい値を決める | メモリ、JNI、画像解放、OCRタイムアウト、SAF、低容量時のI/O |
| 実機表示・操作 | 小画面・大画面、ライト/ダーク/システム、文字拡大、TalkBackを使い全主要画面を巡る | 操作とエラー復旧が可能で、文字切れ、重なり、到達不能なボタン、読み上げ不能な操作がない | Composeレイアウト、semantics、タッチ領域、状態復元 |
| 配布物の実インストール | 署名済みReleaseの作成と配布経路確定後、対象端末へインストール・更新する | 既存データを保持して起動・移行できる。署名不一致なら既存アプリをアンインストールせず停止する | 署名、applicationId、ABI、minSdk、schema v1→v2移行 |

判定時には、上記だけでなく[今回の継続記録](testing/2026-11-12_CONTINUATION.md)の非実機残項目も確認する。現時点のRelease受入は保留。
